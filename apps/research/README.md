# Durable factor research host

Official Pi Durable **1.1.0**, pi-ai **1.1.0** and Chord **1.1.0** own conversations, submissions, task execution, children, replay, cancellation, usage and compaction. QuaZonai adds original research/trial/selection/exposure facts and small native scientific adapters. There is no second task database, Agent loop, cron or imported internal scheduler.

## Host integration

`openResearch({database,extensions?,modules?,providerModules?,models?,storage?,settings?,thinkingLevel?})` returns `harness/models/registry/start/list/view/watch/stop/tasks/usage/availableModels/close`, plus `submission` and `submissionFor`. The `/api/v3` service opens this same database once and uses the host programmatically. Only one process may own its native SQLite and sidecars. Close suspends work; reopen resumes the same identities.

`start(requestId,input)` retains the original `{goal,publicLiteratureQueries?,model:{provider,modelId},thinkingLevel?,serviceTier?,data,policy}` and rejects changed input under the same ID. Startup reconciles committed Requests against public `tx.submissionByRequest` and repairs only missing submissions through `Conversation.submit`. Original admissions use the original goal; recorded continuation intents use their predecessor-linked continuation input. Existing native submissions, including done/unanswered, are never repeated. A later final/owner stop prevents pending admission repair. No raw `Tx.createSubmission` admission is used.

New starts cannot claim the deterministic numeric continuation namespace. The service may pass `start(requestId,input,true)` internally only when repairing or replaying an already persisted original Application admission from before that rule; no HTTP field enables this path. Host still checks the encoded native conversation and refuses cloning an actual legacy continuation receipt. Existing original Requests receipts replay unchanged.

An owner-authorized `resume(conversationId, previousSubmissionId)` admits a new normal input in that same conversation after either its latest input is `unanswered/model_error` with an unfinished Study, or a latest `done` input has an unselected `STOPPED` Study (`trialId:null`, `result:null`). Original budget must remain. Selected/assessed finals, aborted or active inputs and mismatched predecessors cannot continue. Before a stopped study continues, one official transaction appends its complete prior final and predecessor to `Study.previousStops`, clears only the current final and saves the deterministic continuation intent in existing Requests. A crash before native input admission is repaired at startup; a subsequent owner stop wins. Duplicate/reopened calls replay the same receipt without another history entry or model round, including older receipts without continuation-intent metadata. Recovery admissions never become original start receipts. Read projections expose original/latest submissions and prior stops. `diagnostics` returns allowlisted model-error categories, not provider text, credentials or thinking. Ordinary status reads do not construct the full transcript watch.

`view` includes native view, Study and the original native `submission` record. Public service projections should expose only submission ID/status, scientific facts and effective agent metadata—not hidden reasoning or raw private transcript. `tasks(cursor?)` paginates native stored records; inspection/usage remain upstream observations, not mirrored task status. `watch` is a disposable native watch; detachment does not abort work.

Close stops new admissions, drains admitted starts, detaches host watchers, then invokes `Harness.close`. Explicit `stop` records owner stop intent and invokes `Conversation.abort(...,{background:true})` for owned work. Neither shutdown nor a local process exit proves a remote provider/downstream cancellation.

## Native tuning

These are owner-configurable public `HarnessOptions.settings` starting values, **not** performance guarantees:

| Setting | Default / unit |
| --- | --- |
| `stream.timeoutMs` | not set; retired configured values are ignored |
| `stream.maxRetries` | 0 SDK retries; avoid multiplying durable attempts |
| `retry` | enabled, six retries, exponential base 2000 ms, native delay cap 60000 ms |
| `compaction` | official defaults: enabled; reserve 16384, recent 20000, background 32768 tokens |
| `progress.partialIntervalMs/outputIntervalMs` | 250 milliseconds |
| `contextRetentionMs` | 600000 milliseconds |
| tool execution | native parallel reads; scientific mutation/finalization tools make their round sequential |

Load the same live host settings/modules on restart; settings themselves are not persisted. Model and effective thinking are persisted through native `configure`/`pi.agent`. The owner default is `medium`, explicitly clamped by public pi-ai capabilities (nonreasoning models resolve to `off`). Availability reports supported/effective levels, not reasoning content.

Explicit `thinkingLevel: "max"` is available when the official model catalog declares it; unsupported levels are rejected. Official Pi supports levels through `max`, with no `ultra` level. [Pi thinking capabilities](https://github.com/earendil-works/pi/blob/v1.1.0/packages/ai/src/models.ts#L1222-L1232).

For the official OpenAI Responses provider (ChatGPT subscription or API key) and legacy Codex subscription provider, `serviceTier: "priority"` requests Fast mode and `"default"` requests standard mode; omission keeps the provider default. Model availability lists these supported `serviceTiers`. The original choice survives continuation, compaction and restart and is sent through pi-ai's public payload hook, since Durable's stream settings omit this field. Other APIs reject an explicit tier. Fast availability is determined by OpenAI; requesting it does not guarantee an actual speedup or establish the account's billed tier. Fast consumes included subscription limits at 2.5 times the standard rate; purchased credits and API keys use the applicable OpenAI pricing. [OpenAI Fast mode](https://learn.chatgpt.com/docs/agent-configuration/speed#fast-mode), [Pi OpenAI provider](https://github.com/earendil-works/pi/blob/v1.1.0/packages/ai/src/providers/openai.ts), [Pi Codex request options](https://github.com/earendil-works/pi/blob/v1.1.0/packages/ai/src/api/openai-codex-responses.ts#L79-L84).

Quota/billing/auth failures remain final; there is no model/provider fallback. QZ injects no model request or discovery timeout. Upstream SDK/provider quotas and native timeout semantics still apply; this is not a promise of unlimited provider execution. Pi Durable 1.1.0 has **no public global numeric concurrency limit**; sequential is per round, not a limit across conversations.

The research-specific native `GenerationTask.onYield` hook continues only studies lacking a final record, under the original trial budget/criteria. The running native host supplies successor generations; a response boundary is not a scientific stop rule and requires no separate background loop. This does not promise execution after the host closes. Conversation-scoped decisions survive successor generations and crashes. Repeating an unchanged scientific trial ledger closes orchestration with `research_no_new_evidence`; a new citation or reworded hypothesis alone does not change that ledger. This is a technical evidence gap, never economic rejection. Exhausted search admits one conversation-owned official closure Task which waits for original admitted trials, freezes their comparison and preserves ties/frontiers; it does not require another model response. Model finalization and owner stop preserve original budgets and terminal request identities.

Native `control.terminate` ends a round only when every tool returns it. Final tools should be called alone. The research `ToolTask.afterTool` hook marks subsequent successful read/error results terminal once final is recorded; scientific adapters refuse additional computation with terminal feedback. A read preceding final in a mixed round can still cause one more model request. Upstream engine semantics are unchanged.

## Models and extensions

Official `builtinModels` uses configured host environment, the app-owned `${database}.auth/credentials.sqlite` store and trusted provider modules. It **does not** reuse Pi Desktop credentials automatically. No arbitrary credentials files are searched/read, secrets returned, or paid discovery probes run. Directory/file modes are 0700/0600; serialized SQLite mutations implement official login/refresh/logout. Back up this store with the original research database. Trusted `providerModules` default-export native pi-ai Providers; `models` can be supplied directly (its caller owns credentials). Boot refresh is offline metadata-only.

Trusted `modules` default-export official `defineExtension` bundles. Research/brief/finish are in `plugins/research.ts`; `factor-wasm.ts` registers the owned factor child, `heldout-wasm.ts` selects and assesses once, and optional catalog/volume/validation-compare modules use the same native facts. `factor_finalize_group` in the same heldout bundle assesses two or more original recorded selections together; every selection must be made before any final exposure, include the caller and use the same sealed criteria. It uses one shared exposure, retains each original native child/result and returns no tuning feedback. A previously finalized window cannot be reopened to add members. Missing adapters/data remain explicit failures. Keep task names/versions compatible when changing installed extensions so old work can resume.

`plugins/strategy-portfolio.ts` registers `strategy_portfolio_evaluate({hypothesis,members:[{model,weight}]})` and `strategy_portfolio_finalize({trialId,reason})`. Each complete ensemble, including invalid weights/WAT or native failure, is one original ledger attempt under `max_trials`; members use the same eight-input Wasm ABI. Positive decimal-string weights sum exactly to one; admission never changes the fixed threshold, invested weight, TTL, currency, capital or simulator/fee settings. No untracked member probes run. A distinct owned `qz.strategy-portfolio.evaluate` task executes all members, native exact `blend-targets`, then ONE native shared-account `simulate`.

This extension forecasts from the original causal prefix, clipping iterative event end **and decision cutoff** to validation end, but trades only `[train_end_ns,validation_end_ns)`. Finalization selects the original computed proposal, checks normalized original criteria and the sealed binding, reserves the existing exposure once, then trades `[validation_end_ns,event_end_ns)` with full-prefix warmup. Iterative model feedback puts original native account statistics first, followed by pooled component IC/count summaries without repeated requests or per-asset diagnostic arrays. `partitions` are explicitly labelled as component 0's observational factor diagnostics, not ensemble/account metrics. Final feedback is only terminal acknowledgement. The original child outcome retains raw native evidence/curve at `outcome.result.native`, referenced by `evidenceTaskId`; Study retains the original complete summary unchanged. Model-facing projections are not a second result store.

An explicit `strategy.kind: "cross-market-threshold"` uses a declared training-only `instrumentIds` universe instead of a base instrument. A complete proposal can supply `allocations:"ALL_EQUAL"` to include every original admitted market without copying a paged list back into the tool call. The resolver uses the unchanged universe/order,18decimal-place equal base weights and an exact remainder on the last original instrument; the registered literal and original policy determine the complete allocation, which is expanded in native child evidence and reused by validation/final/replay. This is explicit selection, not a default, a new universe or a guarantee of investment/fills; inactive signal capacity stays cash under the original mapping. Existing `allocations:[{instrumentId,weight},...]` for at least two distinct admitted markets remains supported, with exact positive weights summing1, plus the original Wasm members/member weights. All markets share the original **total** starting capital; `investedWeight` scales their combined risky budget. Candidate market choices and failed allocations consume the same original attempt budget. Forecast/diagnostic computation selects only those registered markets while retaining their full causal prefix and original request provenance.

Cross-market target frames follow the union of actual BAR availability clocks. Missing/expired scores request cash rather than an invented signal; exact allocation-product dust also remains cash. Each full target vector explicitly records `rebalance_instrument_ids`: only markets actually observed at that clock can submit native orders. This is not padding sparse BARs or trading an unobserved market at its old book. Native residual holdings and all their account marks remain in equity even when a stale desired weight becomes zero; desired cash never claims a partial cancellation released actual funds. Omitted scopes preserve the original synchronized target behavior. Validation, once-only owner final and portfolio replay resolve the same original market allocations; final values never become model tuning feedback. Multiple tokens alone do not establish independent events, YES/NO relationships or executable arbitrage.

`research_brief({afterTrialId?,limit?})` returns the original objective/data/policy and a compact trial ledger page (10 records by default, at most20 per response). Follow `nextAfterTrialId` as the next `afterTrialId` until null to disclose every trial, including failures and rejections. This is response pagination, not a trial-budget limit. `research_trial({trialId})` reads one original current-conversation trial's status/error and validation feedback without computing or consuming another attempt. It applies the same portfolio projection to old stored results; full diagnostics remain owner-visible. Neither tool returns final held-out results, raw forecast/return/equity arrays or native child evidence. Recover a result through this read tool rather than submitting the same candidate again.

## Registered PM campaigns

The optional `ResearchInput.campaign` binds the immutable policy, exact metric definitions, original dataset revisions, comparison scope and budget to `qz.research-campaign` in official Durable. `strategy_intake` retains the owner's original goal and actual strategy archetype; unsupported adapters and unresolved boundary statements remain explicit gaps. `research_hypothesis` records the economic mechanism, falsification statement and incremental question before admitted trials. These are model proposals, not verified economic truth. `research_compare` consumes only registered Validation evidence; training fits remain visible in the ledger but are not account candidates. A recommendation requires the frozen preference and complete comparable evidence; no implicit first-place selection resolves ties or a frontier-only mandate.

Install `plugins/fitted-ensemble.ts` for `strategy_ensemble_fit` and `strategy_ensemble_evaluate`. Each is a separate original trial, including failure. The native fit uses full prediction reports generated as part of that fit's recorded task and TRAIN-only expanding folds. Its frozen calibrations and exact learned coefficients, including zero weights, feed `apply-ensemble` before one shared-account replay. Owner evidence retains the original fit request/full reports, fit result and simulation request. Summary-only catalog adapters cannot substitute unavailable full panels. A PM campaign refuses the legacy hand-weighted portfolio and grouped finalization routes. The original native catalog prefix is hashed before and after full-panel generation, retained in the FIT evidence, and verified against the replay catalog before and after every replay; a changed original prefix is rejected. Required matching native commands are `catalog-prefix-digest`, `evaluate-factor`, `fit-ensemble`, `forecast` or `forecast-factor`, `apply-ensemble`, and `simulate`; the downstream PM consumer additionally uses `freeze-ensemble-calibrations`, `study-portfolio`, and `capital-curve` where supported. Its observed spot-account consumer requires `value-observed-spot`, `compare-observed-spot`, and `study-observed-spot`.

Explicit `multi_currency_spot_cash` replay preserves the original cash policy. Its original official task stores a `RESEARCH_DATASET_REVISION_BRIDGE` artifact before invoking `simulate --dataset-revision-id`: a real UUIDv7 identifies this bridge, bound to the frozen campaign revision references, input-metadata digest, source selection, partition and simulation settings. It does not claim the source producer used that UUID, prove catalog byte immutability, or grant new data permission. Owner evidence retains the bridge; replay after suspension reuses its original UUID. Independent replay uses its own frozen scope. A PM account consumer receiving a pure `FACTOR_RESEARCH` intake records `pm_account_consumer_not_requested`; it retains the requested research archetype instead of inventing an account mandate.

Campaign trial counts are hard admission limits. The versioned technical policy `qz.research.resources/1` also bounds model generations to `max(24, 12 × maximumTrials)`, saturated at the largest safe integer; its original generation IDs survive restart and owner continuation. This allowance measures orchestration, not model dollars or scientific significance. Native elapsed wall seconds are recorded per settled attempt; an interrupted attempt whose full duration cannot be recovered is explicitly `UNAVAILABLE`. There is no trustworthy cross-restart hard timer, monetary meter or byte meter: non-null `nativeComputeSeconds`, `modelSpend` or `dataBytes` hard-cap requests are rejected at admission, never treated as zero or a best-effort cap. Official provider usage remains separately available through the host.

`independentConsumer: "PM_PORTFOLIO"` freezes the selected research candidate and concludes selection without consuming Sealed. The service first freezes the actual allocation method and capital configuration, then owns the independent assessment. Ordinary research keeps its original registered once-only finalizer. Native exposure remains keyed to actual BAR identities/windows; a new campaign or dataset revision cannot reset it. Full comparison freeze and final admission commit together, and replay resumes the same final selection/native child rather than selecting again.

## Literature context

An owner may include `publicLiteratureQueries` in the original research input: 1–3 explicit public topics, each nonblank, at most 500 characters and without control characters. The service also accepts this field in its configured-dataset request form, and Web exposes an optional one-topic-per-line input. These are the only query texts the study may send to paper providers. No query is inferred from the goal, private research input or specification. The system validates the list and restricts selection; it does not decide whether owner-entered text contains a secret.

The built-in `qz.research` extension gives the Agent three literature tools through official Pi Durable tool execution:

- `research_literature_search` accepts a `queryIndex` selecting a topic from the owner's frozen list; the trusted tool derives the actual query rather than accepting model-authored text. It queries the public Crossref, arXiv and Semantic Scholar APIs for paper metadata and available abstracts. No additional literature-provider key is required, but the host must be able to reach these services.
- `research_literature_note` binds a claim, its `supports` / `contradicts` / `background` relation, limitations and an optional excerpt to an existing search and paper. Notes interpret retrieved material; they do not replace or rewrite the original source record.
- `research_literature` reads the saved searches and notes for the original research. Inspection does not call a paper provider or repeat research work.

The separate `qz.literature` fact document lives in the same official Durable storage and retains the original tool-task identity, source receipts and outcomes. Committed results survive close/reopen and are reused on replay and repeated reads. This does not introduce a second task database, alter scientific trial records or grant access to final held-out values.

The search tool's optional `limit` is 1–8 papers across the sources, defaulting to five for a new query. Repeating a selected normalized query reuses its latest saved receipt, including failures. A new tool task with `retryFailed:true` can explicitly retry a latest `partial` or `unavailable` result and save a new receipt while retaining the old failure. Completed/empty results stay reused, and replaying an original task always returns its original receipt. Changing `limit` alone does not cause a fresh search. Only the original owner-supplied list can provide new queries; neither a retry nor a new generation expands it.

Without configured topics, the tool reports `public_queries_not_configured` with an empty source list and makes no provider request. This is an unavailable capability, not a provider failure or a successful empty search. Old studies and saved receipts remain readable; absence of topics prevents new external searches without blocking otherwise admitted scientific work. Retrieval failures likewise do not introduce a new scientific admission gate.

The transport uses one in-flight arXiv request per process with at least three seconds between requests and quotes/escapes the selected topic as literal arXiv search text. Deduplication preserves the first-ranked paper while retaining available abstract metadata from duplicate records, so a metadata-only result does not discard a retrieved abstract.

Search states distinguish `completed`, `partial`, `unavailable` and `no_results`, preserving each source's errors. A successful empty response is different from an unavailable API; neither proves that no relevant literature exists. Missing metadata and abstracts stay absent. The tools do not fetch or read full-text PDFs, bypass paywalls or validate the scientific truth of a citation. Excerpts must come from retrieved material and notes must state the limits of applying it to the proposed study. Literature supports hypothesis development; independent science and profitability remain separate claims.

The service exposes the saved literature with research detail and the Web workbench presents it in the literature tab. Official Faux-provider tests can verify tool protocol, persistence and recovery, while a real-model evaluation must separately establish that the Agent searches, cites and qualifies sources appropriately under an authenticated provider and reachable paper APIs.

## Scientific isolation

The Wasm adapter uses a prepared `data.catalog` and original native request, with optional `data.sealed` for independent final evaluation. Preserve original licensing, source/PIT and availability facts; an existing directory establishes none of them. Iteration truncates the native selection at validation end, including labels. Shared half-open causal partitions use canonical decimal-string boundaries satisfying `start < train < validation <= end`.

Factor-only evaluation accepts original native price/volume BAR catalogs without simulation instrument definitions. It retains exact BAR identities, time ordering, positive finite OHLC and the explicit row budget; it does not invent tick, fee, currency or execution regimes. Ordinary `forecast` stays strict. An explicitly admitted `strategy.forecastMode: "price-volume"` uses `forecast-factor` with the same price-BAR loader for conditional portfolio research; simulation still uses the originally supplied executable definitions and settings. No synthetic fees or default capital are supplied. Legacy absent flags retain the ordinary forecast/portfolio interval behavior.

For a complete registered BAR catalog, `job scan-factor-catalog --catalog PATH --model PATH` accepts `NativeCatalogFactorScanRequestV1` on stdin. It discovers every BAR series through official Arrow/Nautilus and retains one series plus pooled score/label pairs, not constant total memory. Its compact result preserves shared optional fuel, original partitions, pooled IC and observed/empty/warmup-only coverage, without per-asset arrays.

An owner can explicitly bind that request as `data.catalog_scan_request` **instead of** `data.request`, alongside the immutable `data.catalog`. The compact request has `schema_version`, `event_start_ns`, `train_end_ns`, `validation_end_ns`, `event_end_ns`, `decision_cutoff_ns`, `maximum_rows` and the existing native `parameters`; no market list is supplied. `catalog_input` describes this configured all-series scope. `factor_evaluate`/`factor_volume` record the original attempt, clip the iterative suffix and invoke the catalog kernel. `factor_finalize`/`factor_finalize_group` preserve original once-only selection, session exposure and owner-only final results. Existing explicit requests keep their behavior; an ambiguous pair is rejected rather than choosing a scope implicitly.

An owned metadata-only child uses `job catalog-factor-scope --catalog PATH` to read the exact BarTypes, not prices/labels. The private set is retained once per immutable root through the existing native-evidence compressed document parts and reused across trials/conversations; windows contain references, not repeated million-entry lists. Comparisons resolve the original identities across paths/copies, preserving the existing exact-BarType/time-window policy. The set is passed privately as `scan-factor-catalog --scope FILE`; a changed set fails before an outside-scope model is computed. These sets and pooled pairs still require memory proportional to their contents. No root name or cached set certifies freshness, unchanged data bytes, PIT or independent source qualification.

This input mode remains **factor-only**. It supplies no executable instrument/fee definitions, dynamic shared-account policy or portfolio binding; account tools reject it explicitly and such factors are not combinable through that unsupported binding. No engineering example is a market/model-quality evaluation, financial result or replacement admission. Installed assets and original study requests are not updated by changing this code.

Trials are recorded before computation; FAILED stays FAILED after recovery. Original proposals, comparison and selection persist. Session-wide exposure is keyed by actual native BAR identity/windows: renamed datasets, copied catalogs, new roots or forks cannot make exposed samples unseen. Final metrics/failure are owner-visible, never model-facing tuning feedback.

For prefix-only portfolio studies, the exposure check also retains the original sealed suffix extent; a new root cannot bypass prior final exposure by presenting only its research-visible prefix. No sealed values are copied into that prefix.

WABT compiles model WAT; an owned official Task runs the real `job evaluate-factor --summary-only`. Omitted/null fuel stays unmetered; explicit scientific budgets stay explicit and results echo the original normalized request/consumed fuel (null when unmetered). QZ adds no process timeout, memory ulimit or adapter output cap; retired factor timeout/memory variables are ignored. Actual provider/OS/hardware limits and allocation/I/O failures remain possible. Provider credentials are not inherited; official environment cleanup joins locally cancelled processes. Use `QZ_SCRATCH_DIR` for native temporary files (tests use `PI_SCRATCH_DIR`). Missing values stay null and computation is not qualification/profitability.

## CLI and verification

Installed operations use the [CLI](../cli/README.md) and [service Skill](../../skills/quazonai/SKILL.md). The old Rust client/bridge commands are not this workbench's API. The optional `src/main.ts` is a private loopback-only host, not the public service; `research.example.json` documents native settings.

```sh
npm --prefix apps/research run typecheck
npm --prefix apps/research test
```

The short suite exercises actual official SQLite/Faux/HTTP/children, SIGKILL safe/unsafe/committed-failure and admission-gap recovery, private credential persistence/serialization, persisted provider backoff/quota/auth, finite evidence-based continuation, mixed-final/read behavior and actual watcher detach. PM checks cover atomic trial/usage settlement, budget closure, frontier preservation, independent-consumer isolation and reopening the same frozen final/native child. The fitted protocol subprocess verifies command wiring/calibration application and explicitly does not establish numerical solver quality. `apps/job/tests/factors.rs` launches `test/native-science.ts` with real mixed-asset native catalogs and the real kernel to verify IC, exposure/final isolation, unmetered omitted/null fuel and explicit scientific fuel exhaustion; `apps/job/tests/ensemble_fit.rs` checks the actual native fitting method. Faux controls model protocol only: these checks prove neither model judgment, real-market/account quality, profitability nor 24-hour unattended acceptance.
