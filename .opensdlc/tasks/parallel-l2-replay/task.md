# Parallel L2 replay

目标：在保留共享账户、费用和事件时间顺序的前提下，让盘口读取通过 CLI、Skill 和页面配置 CPU 核数，默认 1 核。运行中的回放保持原版本，新的实现只影响后续任务。

当前 `economic.rs` 用单个全局时间堆按顺序消费成交和盘口，随后更新共享账户；不能把账户拆成独立标的后合并。`source_books.rs` 的源索引目前是线程局部缓存，若直接在八个线程分别打开同一来源，会重复装载大型索引。盘口快照读取可独立预取，最终事件仍须在原堆中按相同时间及标的顺序提交；每个标的的读取顺序、异常、checkpoint 计数和退出行为必须保留。需要共享来源索引并限制预取量，避免当前内存与磁盘压力恶化。

当前状态：设计和接口检查中，尚未实现或部署；用户当前回放 24562 在原版本运行。

已在独立工作区将盘口来源索引缓存从线程局部改为进程内共享的弱引用缓存，供后续工作线程复用；尚未编译、验证或接入并行读取，当前回放仍运行原二进制。

用户澄清：核数应可调整，不能默认固定为 8。已接入按回放捕获的核数设置、CLI 和页面，原运行中的任务不改变；待编译与结果一致性检查。

当前实现已通过 Rust 编译检查、各相关 TypeScript 类型检查及设置接口测试；串行与并行结果比较仍在编译测试依赖，未部署，尚未确认实际加速。
